# 框架完成后的真实数据系统验收

用户明确要求：全部导航框架完成后，由开发代理自行寻找 rosbag，
在 asus 主机对本系统进行系统测试。此项为最终交付必做工作，不能以合成单元测试替代。
当前状态：待执行；尚未选择或下载数据，不代表任何真实数据测试已通过。

## 执行顺序

1. 完成计划内导航模块及端到端启动，先通过现有构建和软件回归。
2. 自行检索公开数据，优先选择与 MID-360/Livox、IMU 和室内/坡道/重复结构场景兼容的数据；
   从数据发布方核验下载来源、许可、格式、消息类型、逐点时间、频率、TF、外参和真值。
   使用独立测试目录，记录来源链接、版本、文件大小与 SHA256，不提交大体积 bag。
3. 编写显式数据适配配置。必要的 ROS 1→ROS 2 或消息转换须保留原始观测时刻和点字段，
   对转换后的帧数、时间范围及几何进行检查；不能只重命名话题便视为兼容。
   数据标定与测试机配置独立，不冒充实车标定。
4. 使用独立 ROS_DOMAIN_ID、use_sim_time 与 /clock 回放，隔离物理串口和底盘输出。
   缺少绝对云台观测时，只能在适用数据上使用明确的固定传感器测试配置，
   不能伪造动态编码器、轮速或实测停车反馈来宣布硬件链通过。
5. 真实数据模块回放与导航闭环分别测试。录制好的传感器轨迹不能随新控制命令改变，
   因此 bag 回放本身不证明闭环导航到达或真实制动；导航闭环使用仿真/硬件反馈并注明来源。
6. 保存可复现命令、配置、日志、指标和失败样例；修复发现的问题并重新运行受影响项目。
   测试代码、配置和报告以中文 commit 推送 kswlt/Adam_nav_2027，保留不足与未覆盖项。

## 覆盖范围

| 范围 | 主要检查 |
| --- | --- |
| 数据入口/TF/状态 | 字段、单位、逐点时间、外参、TF 所有权、时间对齐、断流与错误输入拒绝 |
| Point-LIO/EKF | 连续性、漂移、协方差、轨迹与真值对比；有真值才报告 ATE/RPE，无真值注明限制 |
| 建图/回环 | 关键帧、相邻约束、正确/错误回环、优化残差、原始点云重建、官方对齐及地图版本 |
| 冻结地图定位 | 正常跟踪、初值偏差、观测丢失、受限恢复、重复结构误匹配和版本拒绝 |
| 环境/规划/控制 | 障碍、地形、窄道、路径/轨迹/足迹验证及控制输出约束；使用能支持该项的输入 |
| 系统监管 | 健康心跳、停车保持、旧任务取消、新任务放行、缓存不重放和串口边界 |
| 资源与稳定性 | 各进程 CPU/RAM、处理时间、队列/丢帧、地图/磁盘规模、回放速率与长时间运行 |

优先覆盖正常序列、带回环序列和困难场景；数据集不具备的属性不能列为已覆盖。
在真实数据上保留基线结果，再评估增强模块；不根据一次结果随意放宽验收门限。
实车专属动态云台、my_serial_py 通信、下位机 watchdog 与制动验收仍需对应实车数据/联调。
最终报告明确区分真实 bag、显式仿真输入及实车证据，不能把公开数据回放称为完整实车验收。
